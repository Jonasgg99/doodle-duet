# Doodle Duet

Asynchronous draw-and-guess game for Jonas, his girlfriend and a few friends on Android phones: each game has two players, and a player can have several games. Private, not for wider release. Installable PWA.

## Architecture
- Static site: plain HTML/CSS/JS ES modules, no build step, no npm. Same pattern as `D:\Apps\choice-timer`.
- `game.js`: pure rules (guess matching, scoring, word picks, replay timing). Covered by `tests/game.test.mjs`.
- `store.js`: storage with two backends behind one interface. Firebase Realtime Database + auth when `firebase-config.js` has a config: everyone starts anonymous, and `signIn()` links a Google account by pop-up (keeps the uid; redirect sign-in breaks because Pages can't host Firebase's auth handler). If the Google account already has a player, it signs in as that one (new uid, page reloads). Otherwise local mode (localStorage, one identity per browser tab, sign-in only flags the tab). `?local` in the URL forces local mode.
- `app.js`: UI, drawing canvas, replay. Routes: no hash = your games list, `#new` = start a game, `#<id>` = a game. A first visit makes a player (name + Google sign-in) before any of them. The games list reads only `players`, `cur` and the current turn's `drawer`/`status`/`n` of each game, never drawings.
- `i18n.js`: the app's own text in English and Norwegian Bokmål (`translator(lang)`; plurals are functions). The phone's first language picks it (nb/nn/no → Norwegian), the switch on the games list overrides it (localStorage `dd_ui`, reloads). `index.html` text carries `data-i18n` keys that `app.js` fills at start; `game.js` returns codes, never text. Text for the other player (notification, share sheet) uses their language from the game, else the sender's. `tests/i18n.test.mjs` fails on a key missing in either language.
- `words.js`: English and Norwegian word lists by difficulty, with adult words mixed in (the `ADULT` block, listed in `ADULT_WORDS`; each game includes them unless switched off).
- `FIREBASE-RULES.json`: the only access control. Data lives under `doodleDuet/games/<id>`. Editing the file does nothing until it is pasted into the Firebase console (Realtime Database > Rules > Publish).
- `firebase-config.js` is public by design (Firebase web config), not a secret.
- Notifications (web push): `push.js` subscribes the phone (from the waiting screen) and asks the Worker to notify the partner when a drawing is sent; `sw.js` only shows notifications (no fetch handler, no caching). `worker/` is a Cloudflare Worker (`doodle-duet-push`) that encrypts (RFC 8291) and VAPID-signs (RFC 8292) the push, with no dependencies; it accepts only this site's origins, real push-service endpoints and links to this site. `push-config.js` holds the Worker URL and VAPID public key (public); empty values turn notifications off. The VAPID private key lives only in the Worker secret `VAPID_PRIVATE_JWK`; `tools/vapid-keys.mjs` makes a new pair (see its header) and every phone must then opt in again.

## Data model
`players/<uid>/name`: the player list you pick partners from; anyone signed in reads it. `users/<uid>/games/<id>: true`: your games list, private; the game's player a may add it to player b's list. `games/<id>` (10 random characters; `main` is Jonas's game from before lists, added to its players' lists when they open theirs; older ids still open via `#<id>` or `#g=<id>`): `lang`, `drawSecs` (always 60 for new games), `wordLevel` (`easy` / `mixed` / `hard`, absent = mixed; either player changes it any time; an unpicked word choice switches to that setting's words, the same ones each time within a round), `adult` (false = adult words left out; absent = included; chosen when starting a game, either player changes it any time, an unpicked word choice is drawn again), `players.{a,b}.{uid,name,lang}` (lang: the app language that player reads, written on create, join and when they open the game), `push.{a,b}` (that phone's push subscription `{endpoint, keys}`, removed when the push service says it's gone), `cur` (current turn key), `turns.t000…`. A turn has `drawer`, `status` (`draw` → `guess` → `done`), `choices` (`{word, level}`), `choiceSets` (the choices each word setting got this round, while choosing), `word`, `level` (word list it came from; older turns have `difficulty` instead), `strokes` (JSON string of `{c,w,p:[x,y,t,…]}` on a 1000×1500 grid), `guessStartedAt`, `guesses` (`{g, t, r}`, r = correct/close/wrong), `result` (`{correct, ms, drawerPts, guesserPts}`; older rounds also have `beforeReplayEnd`), `note` (`{text, at}`, the guesser's message to the drawer, max 120 chars, written from the result banner). The score is shared by the two players: points (each finished round once, the larger of `drawerPts`/`guesserPts`) and the streak of rounds guessed right in a row; both derived from turn results, never stored. Word level picks the lists (easy; easy + medium; hard) but not the points: scoring is the same for every word.

## Testing
- Unit: `node --test "tests/*.test.mjs"`
- End to end (local mode, headless, simulated phones): start `python -m http.server 8124`, then `node tests/two-player.e2e.mjs [screenshot-dir]` (rounds, banners, seat move, hostile game) `node tests/lobby.e2e.mjs` (first visit, games list, picking a player, two games at once, `main` in the list) and `node tests/i18n.e2e.mjs` (Norwegian and English phone in one game, the language switch, 360 px width). Uses Playwright from `D:\Apps\quiz-maker` (override with `PLAYWRIGHT=<path to index.mjs>`); this repo installs nothing.
- Notifications: unit tests check the Worker's encryption against the RFC 8291 test vector; `node tests/push.e2e.mjs` (needs the :8124 server) covers opt-in, notify-instead-of-share-sheet, dead subscriptions and the service worker showing a push. It runs Playwright's full Chromium (`channel: "chromium"`), because the default headless shell always denies notifications.
- In Firebase mode two tabs in one browser share one identity; use local mode or two browser profiles to play yourself.
- After a deploy, phones can briefly mix old and new files (GitHub Pages caches each for 10 min); an inline script in `index.html` re-downloads everything and reloads once if `app.js` hasn't set `window.__ddStarted`. Covered by `node tests/stale-deploy.e2e.mjs` (needs the :8124 server). Keep the file list in that script in sync when adding files.
- Live test: `node tests/firebase.e2e.mjs [base-url]` makes "zz test" players (skipping Google via localStorage `dd_skip_google`), plays a new game by link, checks what the rules refuse, and removes its players at the end. Never point a test at the `main` game in Firebase mode: that would take the real game's seats.
- A seat belongs to a uid. Before Google sign-in every browser is a different player (Messenger's in-app browser and Chrome too; Google refuses sign-in inside in-app browsers); signing in with the same Google account gives the same player everywhere. Seat b also moves with player a's "Let … join again" button (clears `players/b` and `push/b`; turns and scores stay with the seat), then the new browser joins. A lost seat a has no in-app fix: in the Firebase console set `doodleDuet/games/main/players/a/uid` to the new browser's uid, or delete the game (scores lost).
